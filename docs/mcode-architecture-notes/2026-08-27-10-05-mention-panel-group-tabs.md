# `@` 引用面板改用 up-tabs 分组

**文件**：`2026-08-27-10-05-mention-panel-group-tabs.md`

## 现象（用户原话）

> @弹窗的内容用up-tabs区分

原先四组（智能体 / 文件 / 会话 / 提交）在一个 `scroll-view` 里竖排堆叠，每组带一个组内标题
和计数。结果多时要一路滚过不关心的组才能找到目标。

## 一、现成对照就在同一个文件里

`ConversationDetailInteractivePane.vue` 里的**多问题分栏**（`up-tabs` + 只渲染当前题）已经把
这套形制走过一遍，包括「单问题不分栏」和「换一组问题要重置下标」那些坑（见
[[2026-08-20-20-15-acp-error-surface-and-question-tabs]]）。本次照它来，没另起一套：
`keyName="title"` + `:scrollable="false"` + `activeStyle`/`inactiveStyle`。

## 二、四组固定，顺带消掉一个每次按键都会触发的坑

用户选了「四组固定全显、空组置灰」。这个选择**顺带解决了一个我本来要专门处理的问题**。

原先渲染用的是 `mentionVisibleGroups`（过滤掉空组），而 `buildMentionReferenceGroups` 每次按
query 重新过滤 —— 所以**每敲一个字，可见组集合都可能变短**。如果用下标记 tab，下标停在第 3 个
tab、新结果只剩 2 组时内容区就是空白。这与问题分栏那个「换一组问题要重置下标」同型，但触发
频率高得多（每次输入 vs. 每组问题一次）。

四组恒显之后 tab 集合恒为 4、位置固定，下标不再漂移。

**标签带计数**（`文件 13`）：分栏后看不到其他组里有没有东西，计数是唯一线索。`truncated` 时
加 `+`（`文件 20+`）—— 不标的话 20 看起来就是全部，而它其实是 `maxPerGroup` 截断后的数字。

## 三、一次测试冲突暴露了「从状态推不出来」的事实

写完 `resolveActiveMentionKind` 第一版后，两条测试互相矛盾：

- 「当前 kind 那组为空 → 落回第一个非空组」（冷启动该这样）
- 「当前组变空 → 留在原地」（用户正在看该这样）

**两者的输入长得一模一样**（当前组是空的），但正确答案相反。也就是说这个区分**从分组状态本身
推不出来** —— 只有调用方知道自己处在哪种处境。

于是加了显式的 `pinned` 参数：

| `pinned` | 含义 | 当前组为空时 |
| --- | --- | --- |
| `false` | 面板刚打开，当前 kind 只是默认值 | 落回**第一个非空组**（让他直接看到有内容的） |
| `true` | 用户点过 tab，那是他的选择 | **留在原地**，显示空态 |

「用户正在看『文件』组、继续敲字让它变空 → 把他弹到『智能体』组」会让人以为自己点错了。留在
原地并说明「这一组没有匹配项，换个关键词或切到其他分组」，他自己决定下一步。

组件侧用 `pinnedMentionKind: MentionReferenceKind | null` 记「用户选的那一组」，`null` 即未 pin。
`closeMentionPanel` 里清掉它 —— 下次打开 `@` 应该重新落到有内容的组，而不是上次停留的那组
（对新查询可能完全没结果）。

> **教训：测试互相矛盾时，先怀疑「这个区分是不是根本不在输入里」，而不是改一条测试去迁就实现。**
> 这次如果随手删掉一条，就会做出一个「有时莫名跳组」的面板 —— 而且是间歇性的，最难查。

## 四、身份是 kind，不是下标

`up-tabs` 吃的是 `current`（下标），但**当前是哪一组的身份是 kind**。组件里存 kind，需要下标时
由 kind 回查（`activeMentionTabIndex`）。混用会在组内容变化时错位 —— 问题分栏那次踩的正是这个。

`handleMentionTabChange` 里对 disabled 项再挡了一次：理论上 `up-tabs` 的 disabled 项不触发
`change`，但各版本行为不完全一致，不挡的话点空组会把用户 pin 到一个永远没内容的 tab 上。

## 五、顺手删掉的孤儿 CSS

组名和计数都上了 tab 标签，一次只渲染一组，所以这四条规则彻底没了用处，一并删除（`index.scss`）：

- `.mention-group + .mention-group`（组间分隔线）—— 不存在相邻组了
- `.mention-group__header` / `__title` / `__count` —— 组内标题不再渲染

`.mention-group__more`（「结果较多，继续输入可缩小范围」）仍在用，保留。删除处留了注释说明
为什么。

## 六、一次探针把我自己骗了：scoped CSS 的 hash 会变

用 Playwright 拿编译产物 CSS 渲染面板测版面时，第一次量出**面板 921px、比 750px 的视口还高、
`max-height` 完全没生效**。

差点当成 bug 去查，实际是**探针自己错了**：这次改了模板，Vue 的 scoped 属性 hash 从
`afd2b865` 变成了 `f19eeafc`，而探针里硬编码的还是旧值 —— 选择器一条都没匹配上，量的是一堆
没有样式的裸 div。

更麻烦的是 `dist/` 会**累积历史构建产物**（同目录下 30 个 `index-*.css`），`ls | tail -1` 抓到
的往往不是本次那个。清空 `dist/build/h5` 重新构建后才拿到唯一产物。

改对之后：面板 368px、滚动容器 295px（= 590rpx 的上限，与 `/` 面板同源）、内容 592px、可滚、
可见 6.78 行 —— 末行半切，滚动线索也在。

**下次写这类探针**：从产物 CSS 里正则读出 hash 再注入，别硬编码；并且先清 `dist` 再构建。

## 测试

`composerReferences.spec.ts` 新增 `describe("mention group tabs")` **10 例**：四组恒显；标签带
计数；空组 `disabled`；`truncated` 标 `+`；未 pin 时落回第一个非空组；**已 pin 时留在原地
（含全空时也留）**；当前组有结果时保持；全空回到第一组；未知 kind 能恢复；**`pinned` 是区分
两种同形输入的唯一依据**（这条专门锁住那个参数不被「简化」掉）。

**变异探针（3 次，全部命中）**：

- 忽略 `pinned` → 3 红；
- 只显示非空组（丢掉四组固定）→ 3 红；
- 计数不标 `truncated` 的 `+` → 1 红。

每次探针后源文件均 `diff -q` 字节一致。

三道闸：jest **134 suites / 959 tests 全绿**（基线 948，新增 11）；`tsc --noEmit` 恰好 5 条既有
基线错误，改动文件零错误；`uni build` DONE。并**看了截图**确认四组等分、空组置灰、只渲染当前
组、组内标题已消失。

## 原生 iOS / Android 复刻要点

1. **分组集合固定，不要「只显示有结果的组」。** 后者会让 tab 位置随每次按键漂移，用户每敲一个
   字都要重新找自己那一组；固定之后还顺带避免了「下标停在已消失的 tab 上」渲染空白。
2. **空组置灰而不是隐藏**，并在点击层再挡一次 —— 别指望组件的 disabled 一定拦得住。
3. **tab 的身份是分类标识，不是下标。** 存 kind、渲染时回查下标。存下标会在集合变化时错位。
4. **「当前组空了要不要跳组」取决于这一组是不是用户亲手选的** —— 这个区分从分组数据里推不出来，
   必须由调用方显式传入。用户选过就留在原地（跳走会让他以为点错了），没选过就落到有内容的组。
5. **关闭面板时清掉「用户选过哪组」**，否则下次打开会停在一个对新查询没有结果的组上。
6. **标签上要带计数**，分栏后那是判断「别处有没有东西」的唯一线索；被截断时要标出来（`20+`），
   否则截断后的数字看起来就是总数。
7. **改成分栏后记得删掉组内标题相关的样式** —— 它们的信息已经移到 tab 上，留着就是孤儿规则。
8. **用产物 CSS 做版面验证时，scoped 样式的 hash 会随模板改动变化**，要从产物里动态读取；并且
   先清构建目录，否则会量到上一次的产物。

## 待观察

- **面板头部的「匹配 N 项」现在与 tab 上的计数有些重复**（N 是四组总数，tab 上是各组数），
  信息不重复所以留着了，但如果实测觉得吵，头部那个可以去掉。
- **`mentionVisibleGroups` 现在只被计数用**（不再驱动渲染）。它还有意义，但名字里的
  "Visible" 已经名不副实 —— 现在可见的是「当前那一组」。改名会牵动 `mentionResultCount`
  和 `mentionPanelHint`，本次没动。
- **`@` 面板的行高（44px，带两行文本）与 `/` 面板（31px）不同**，590rpx 在它上面是 6.78 行、
  末行半切，恰好也成立。但这是巧合而非设计 —— 上一篇「待观察」里担心的那条在这里没有发作，
  以后调那个共享变量时仍要两个面板都量。
